# ST-Link: серийные номера в info

Команда: `info.cmd`. Общее ТЗ: [действующий черновик](../TECHNICAL_SPECIFICATION.md), раздел 4.5. Прежнее частное ТЗ info ревизии 2 сохранено в [архиве](../archive/TECHNICAL_SPECIFICATION_INFO_R2.md); таблица переноса требований находится в приложении C общего ТЗ.

Если J-Link Commander не завершил перечисление за 10 секунд, в разделе USB-программаторов появится сообщение о тайм-ауте J-Link и совет проверить USB-подключение и повторить `info.cmd`. Это не означает отсутствия J-Link или неисправности найденных ST-Link. Остальные разделы обзора выводятся как обычно.

Источник списка теперь выводится явно. Если установлен CubeProgrammer с поддержкой `stlink-only`, используется `STM32_Programmer_CLI.exe -l stlink-only`. Это режим перечисления без подключения к MCU согласно локальной справке CubeProgrammer 2.19/2.23. Сокращение `-l st` не используется: оно может запускать общий список интерфейсов.

В резервном режиме используется список Windows USB. Значение наподобие `7&36CC77E7&0&2` является идентификатором экземпляра, а не подтверждённым серийным номером. Выводится «серийный номер недоступен» и отдельный USB ID. Такой ID нельзя копировать в `-Serial`.

Даже CubeProgrammer при `DEV_CONNECT_ERR` может вернуть Windows ID вместо номера. Скрипт проверяет формат, показывает предупреждение, не угадывает serial и не сопоставляет устройства по позиции. В этом состоянии закройте другие приложения, использующие программатор, и повторите перечисление. По одному этому сообщению нельзя установить причину ошибки доступа.

Если опция не поддерживается, процесс завершается с ошибкой, превышает время ожидания либо формат вывода неизвестен, пробуется следующая установка, затем Windows. Списки разных источников не объединяются по индексам.

Основные операции прошивки, backup и erase этой доработкой не изменяются.
