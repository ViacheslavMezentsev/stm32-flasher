# Изоляция тестов

**Русский** | [English](isolation.en.md)

## Что проверено в коде

Штатный runner запускает каждый `Test-*.ps1` в отдельном процессе. Наборы,
которым нужны файлы, используют уникальные `tests/.tmp-<имя>-<GUID>`. Переменные
окружения, функции-заглушки и Add-Type относятся к процессу, не к машине.
При просмотре наборов не найдены изменения системного реестра/окружения или
сетевые слушатели с фиксированным портом. Это аудит кода, не защита ОС.

| Ресурс | Наборы | Решение для опыта |
| --- | --- | --- |
| Mutex, рабочая папка | DirectoryLock | Отдельная копия; mutex зависит от полного пути |
| Зависшие потомки, PID-файлы | InventoryTimeout | Свой EXE/каталог; контролировать всё дерево процессов |
| ZIP, dist, GITHUB_OUTPUT | PackageLayout | Упаковка выполняется в собственном fixture |
| Настройки, ответы меню, env | Setup, LaunchConfig | Свои cwd/TEMP/TMP, отдельный процесс |
| Вложенные runner, каналы, тайм-ауты | TestRunner | Собственные логи и подтверждение окончания потомков |
| Много запусков CMD и EXE-заглушки | CoreControl, Verify, FlashEntry | Отдельные копии; полный опыт с ними ещё нужен |

GUID в имени каталога недостаточно для утверждения, что параллельность безопасна:
остаются TEMP, унаследованные пути модулей, дочерние процессы и нагрузка CPU/диска.
Короткие пути копий важны для Windows PowerShell 5.1 и вложенных стендов.

## Методика

Один снимок чистого коммита, одинаковый перечень/порядок наборов, отдельная копия
архива на КАЖДЫЙ набор и при одном, и при двух worker. Ограничение worker означает
число активных наборов, а не всех дочерних процессов. SHA-256 проверяется до/после;
логи, временные папки и результаты раздельны. Ошибка не запускает скрытый retry.

Дерево процесса заключено в Windows Job Object до начала теста: bootstrap ждёт
разрешения после успешного назначения job. Оставшийся потомок означает FAIL,
даже если родитель вернул 0; дерево завершается, факт сохраняется. Основа:
[Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).
Это не sandbox от недоверенных тестов: профиль пользователя, сеть и устройство
не виртуализируются. Опыт использует только аппаратно-независимые штатные наборы.

При запуске PS5.1 из Python нельзя слепо наследовать `PSModulePath` родителя PS7:
это привело к недоступности `Get-FileHash` в первом последовательном прогоне.
Прототип удаляет эту переменную только из окружения дочернего процесса, чтобы
оболочка построила собственные стандартные пути. Предварительно проверяются
`Get-FileHash` и `Add-Type`. Пользовательские/машинные настройки не меняются.

Синтетические сценарии проверяют совпадающие имена файлов, env, реальное
перекрытие двух worker, ненулевой код, изменение исходника, тайм-аут и оставшегося
потомка. Затем сравниваются шесть наборов из таблицы (без CoreControl/Verify/
FlashEntry), обе оболочки. Порядок: PS5.1 1→2, PS7 2→1; прогрев перед каждым
режимом. Подготовка отделена от выполнения, все отсчёты и FAIL сохраняются.

## Результат 12.10.2026

Чистый коммит `f135282`; Windows, i9-13900HX (24 ядра / 32 логических процессора),
Python 3.11.9, PS5.1.26100.9444 и PS7.6.6. Один опыт на режим/оболочку,
шесть наборов из 23. Все 24 исполнения PASS: состав одинаковый, без пропусков
и дубликатов, отдельные пути, SHA-256 неизменны, оставшихся процессов нет.

| Оболочка | Worker | Подготовка, с | Выполнение, с | Всего, с |
| --- | ---: | ---: | ---: | ---: |
| PS5.1 | 1 | 4.51 | 168.76 | 173.51 |
| PS5.1 | 2 | 8.07 | 93.24 | 101.37 |
| PS7 | 1 | 5.35 | 217.20 | 222.61 |
| PS7 | 2 | 8.13 | 135.88 | 144.07 |

Всего включает финальный контроль; выполнение включает проверку каждой копии.
Наблюдаемое ускорение по общему времени: 1.71x / 1.55x. Это не прогноз для
GitHub или всего комплекта. Подготовка тоже менялась между попытками; одного
замера недостаточно для вывода о её стабильной стоимости.

Исходный последовательный FAIL из-за PSModulePath сохранён и исключён из
сравнения. После исправления синтетические контракты повторены в PS5.1/7,
затем все четыре реальных режима выполнены заново на прежнем снимке. Никаких
изменений рабочих CMD, порогов тестов, версии или штатного workflow.

## Следующий этап

Один опыт на режим не устанавливает стабильный speedup. Шесть наборов не заменяют
полную матрицу из 23. Штатный локальный CI и GitHub пока остаются последовательными
внутри каждой оболочки; исследовательский прототип не включён в CI и релиз.

Механизм перенесён в opt-in ci/Invoke-Isolated.ps1 с регрессиями:
раздельные копии, очередь из 1/2 worker, Job Object, таймаут набора и общий
бюджет оболочки, проверка полноты результатов. Test-IsolatedRunner добавлен
к штатному комплекту (теперь 24 набора). Запуск: [CI](README.md).
Полный повтор 12.10.2026, WorkingTree, 2 worker, Python 3.11.9:

| Оболочка | Наборы | Подготовка, с | Выполнение, с | Всего, с |
| --- | ---: | ---: | ---: | ---: |
| PS5.1.26100.9444 | 24/24 PASS | 28.78 | 389.40 | 418.42 |
| PS7.6.6 | 24/24 PASS | 29.94 | 519.07 | 549.07 |

Без пропусков/дубликатов, целостность всех копий PASS, оставшихся процессов нет.
В первой попытке Test-Ci PS7 вернул 0, но Job Object показывал один процесс;
внешний runner сохранил Failed. Его тип тогда не записывался. Теперь после
выхода root предусмотрено до 1 с на завершение дерева, PID/образы сохраняются;
долгоживущие потомки по-прежнему дают Failed. Контракт короткого потомка прошёл;
в полном повторе этот случай не воспроизвёлся. Исходный отказ не стёрт.

Это один полный замер режима 2, не сравнение полного 1/2 и не проверка GitHub.
После снимка отдельно исправлено разрешение относительных путей PS-обёртки;
финальные 8/8 контрактов runner прошли адресно в обеих оболочках.
Следующий этап: опыт runner на GitHub и сопоставимая полная база одного worker.
Отдельно проверить справедливое распределение долгих наборов и общий тайм-аут.
Quick не должен заменять полное покрытие; ускорение принимается только при
одинаковом составе, отсутствии пропусков/дубликатов и сохранении всех отказов.
