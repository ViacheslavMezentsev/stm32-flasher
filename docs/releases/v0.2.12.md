## stm32-flasher 0.2.12: исправление запуска без аргументов

Исправлен [issue #1](https://github.com/ViacheslavMezentsev/stm32-flasher/issues/1):
в версиях 0.2.10–0.2.11 команда `flash.cmd` без аргументов могла молча завершаться
до запуска основной логики. Причина — обработка пустой строки аргументов в CMD.
Версия 0.2.9 не затронута.

Восстановлен обычный сценарий: один HEX в папке выбирается автоматически,
используются сохранённые настройки движка и отладчика.
Для обновления замените `flash.cmd`; сбрасывать настройки не нужно.

В CI добавлены запуски через CMD с EXE-заглушками CubeProgrammer, OpenOCD и
J-Link: успех, ошибки, отчёты, история, отсутствие HEX и проверка SHA-256.
Это проверки без MCU, не повторная аппаратная приёмка.

Владелец также подтвердил исходный сценарий на плате через CubeProgrammer/ST-Link:
запуск без аргументов, автоматический выбор единственного HEX, успешные запись
и проверка за 3.584 с. Другие движки аппаратно в этом исправлении не перепроверялись.

## stm32-flasher 0.2.12: fix no-argument startup

Fix [issue #1](https://github.com/ViacheslavMezentsev/stm32-flasher/issues/1):
in 0.2.10–0.2.11, `flash.cmd` without arguments could exit silently before reaching
the main logic. CMD handling of an empty argument string was the cause.
Version 0.2.9 was unaffected.

Restore the normal workflow: automatically select the only HEX in the working
directory and use saved engine/probe settings. Replace `flash.cmd` to update;
there is no need to clear settings.

CI now includes CMD launches with stub executables for CubeProgrammer, OpenOCD
and J-Link: success, errors, reports, history, missing HEX and SHA-256 checking.
These are hardware-free tests, not renewed hardware acceptance.

The owner also confirmed the original workflow on a board via CubeProgrammer/ST-Link:
no-argument startup, automatic selection of the only HEX, successful programming
and verification in 3.584 s. Other engines were not hardware-retested for this fix.
