# Контракт doctor

**Русский** | [English](doctor.en.md)

Статус: контракт согласован; реализованы встроенный паспорт и чистые правила.
`doctor.cmd`, сбор окружения и пользовательский вывод пока не реализованы.
Версия рабочего инструмента остаётся 0.3.0; это не изменение опубликованного тега.

## Назначение

Info показывает окружение. Doctor сравнивает наблюдаемые факты с требованиями
и паспортом испытаний, не подтверждая готовность платы или HEX к прошивке.
Будущая обёртка вызывает `flash.cmd -Doctor`. Остальные режимы с Doctor конфликтуют.
Допустимы общие параметры выбора Engine/Probe/Serial/Target/Device, Lang,
справка, версия и DryRun; CLI имеет приоритет над сохранёнными настройками.

Без меню, MCU, st-info --probe, сети, скачивания, миграции и исправлений.
Не создаются отчёт, история, файлы команд или настройки. Help/version обходят
чтение конфигурации; DryRun описывает план без внешних процессов и USB.
Запросы инструментов ограничиваются по времени, stdout/stderr дочитываются
с отдельным лимитом. Результат опроса не должен подменяться старым кэшем.

## Паспорт

JSON встроен в Get-DoctorPassport внутри flash.cmd; внешних зависимостей нет.
schemaVersion=1; baselineRelease=0.3.0. Базовый выпуск не обновляется автоматически
вместе с VERSION: он обозначает происхождение доказательств.

- runtime: Windows 10/11, PowerShell 5.1/7; это контракт поддержки, не точный образ ПК.
- tools: точные проверенные версии, без выдуманных минимальных требований.
- profiles: engine/version/probe/mcu/operations/evidence; список не исчерпывающий.
- evidence: отдельные ссылки на аппаратные записи и CI с заглушками.

Начальная база: CubeProgrammer 2.19.0 и SEGGER V8.32. Для OpenOCD 0.12.0
в аппаратной записи нет полной сборки; список точных testedVersions пуст.
Версия с суффиксом сборки не равна версии без него. Префикс v/V и четвёртый
нулевой компонент файловой версии Cube нормализуются; другие части не отбрасываются.
Запись MCU в паспорте не означает обнаружение или совпадение подключённого MCU.

## Статусы

| Факт | Статус |
| --- | --- |
| Поддерживаемый runtime, корректный JSON, доступный движок | OK |
| Версия совпала с точной проверенной | OK только для версии |
| Версия другая, неизвестная или её запрос завис | WARN |
| Нет настроек / legacy без миграции / выбор ещё не сделан | WARN |
| Несколько подходящих программаторов без serial | WARN |
| Ошибка/таймаут USB либо неизвестный serial, мешающий проверке выбранного | WARN |
| Недопустимый runtime/JSON, выбранный движок отсутствует или не запускается | ERROR |
| Достоверно нет подходящего либо выбранного программатора | ERROR |
| Неподдерживаемая пара движок/программатор | ERROR |
| Явный OpenOCD target отсутствует | ERROR |
| Target/device не заданы, либо доступность target неизвестна | WARN, ограничение операций |
| Нет st-info при OpenOCD без target | WARN, автоопределение ограничено |

Неиспользуемые движки не являются обязательными. Cube/J-Link допустим для
flash/check, но это не разрешает управление ядром; doctor не даёт общий OK
для всех операций. Имя J-Link device проверяется как настройка, не как модель MCU.

Exit 0: нет ERROR, WARN допустимы. Exit 1: ERROR или внутренний отказ диагностики.
Итог всегда оговаривает: MCU, питание, SWD и образ не проверены.

## Данные и проверки

Get-DoctorAssessment принимает только факты, не обращается к ОС и не меняет их.
Runtime: Supported/Unknown/Unsupported; Config: Valid/Missing/Legacy/Invalid.
Engine: State Available/Missing/NotSelected/Unknown, Name и VersionState
Known/Unknown/Timeout/Error. Error здесь означает доказанную невозможность
запуска; непонятный ответ или неподдерживаемый ключ версии означают Unknown.
Inventory.State: Known/Unknown/Timeout/Error. При Known Count и UnknownSerialCount
считаются только для подходящего типа программатора; UnknownSerialCount <= Count.
Probe содержит Type, SerialRequested, SerialFound. Target: Available/Unset/Missing/Unknown;
Device и StInfo — логические признаки наличия. Неизвестный тип программатора
не позволяет сборщику объявлять достоверное отсутствие подходящего устройства.
Результат содержит Findings (Id/Status/Code/Actual/Expected), ExitCode,
NoticeCode и BaselineRelease. Code — стабильный идентификатор для будущих RU/EN сообщений.

Test-DoctorPolicy проверяет паспорт, версии, неоднозначность, доказанные ошибки,
неполные данные и неизменность входов в PS5.1/7. Далее нужны интеграционные тесты:
реальные CMD с EXE-заглушками, обе локали, конфликты режимов, help/version до
конфигурации, DryRun без опроса, ограниченные таймауты и отсутствие записи/миграции.
