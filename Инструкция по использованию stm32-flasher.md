# Инструкция по использованию stm32-flasher

## Назначение

`stm32-flasher` - это Windows-скрипт для прошивки STM32 через ST-Link или J-Link без отдельной установки проекта или сложной подготовки рабочего места. Основной сценарий - положить `flash.cmd` рядом с `*.hex` и запустить его двойным щелчком или передать файл в командной строке.

Скрипт старается оставаться самодостаточным:
- работает как один `flash.cmd`;
- использует `STM32CubeProgrammer`, если он установлен;
- умеет использовать `STM32CubeProgrammer` как со ST-Link, так и с J-Link;
- умеет использовать `SEGGER J-Link Commander` напрямую;
- иначе может скачать и использовать встроенный `OpenOCD`;
- при необходимости использует `st-info` для определения типа подключённого STM32;
- если к ПК подключено несколько ST-Link, позволяет выбрать нужный;
- запоминает выбранный J-Link device и serial, если они были указаны или найдены в логе;
- может проверить SHA-256 файла прошивки до запуска прошивальщика;
- сохраняет историю предыдущих прошивок в `.history`;
- сохраняет лог и HTML-отчёт последней прошивки.

## Что ожидать от поведения

### Обычный сценарий

1. Пользователь кладёт `flash.cmd` рядом с `*.hex`.
2. Подключает ST-Link или J-Link к ПК и плате.
3. Запускает `flash.cmd`.

Дальше поведение зависит от содержимого папки и параметров запуска:
- если рядом только один `*.hex`, скрипт сразу начинает прошивку;
- если `*.hex` несколько, скрипт предложит выбрать нужный;
- если файл `*.hex` передан на скрипт мышкой или аргументом командной строки, он будет использован напрямую;
- если найден `STM32CubeProgrammer`, в прямом сценарии он выбирается автоматически как предпочтительный движок;
- при успешной прошивке отчёт сохраняется, но не открывается автоматически;
- при ошибке отчёт сохраняется и открывается автоматически.

### Что сохраняется после запуска

| Файл/папка | Назначение |
|---|---|
| `.tools\` | Локальная папка инструментов, в том числе OpenOCD |
| `.flash_engine` | Запомненный выбор движка прошивки |
| `.openocd_target` | Запомненный `target/*.cfg` для OpenOCD |
| `.probe_type` | Запомненный тип отладчика: `STLINK` или `JLINK` |
| `.stlink_serial` | Запомненный выбор конкретного ST-Link |
| `.jlink_device` | Запомненное имя устройства J-Link, например `STM32G431CB` |
| `.jlink_serial` | Запомненный serial J-Link, если он был указан или найден в логе |
| `*.hex.sha256` / `*.sha256` | Опциональная контрольная сумма SHA-256 для прошивки |
| `flash_log.txt` | Лог последней прошивки |
| `report.html` | HTML-отчёт последней прошивки |
| `.history\` | Архив предыдущих отчётов, логов и индекс истории |

## Требования

- Windows 10 / 11;
- PowerShell 5.1 или новее;
- подключённый ST-Link или J-Link;
- драйверы ST-Link или SEGGER J-Link Software;
- интернет при первом запуске, если потребуется скачать OpenOCD или полный набор `stlink` tools.

## Способы запуска

### 1. Двойной щелчок по `flash.cmd`

Подходит для обычного использования в Проводнике Windows.

Рекомендуемая структура:

```text
flash.cmd
mcu_lts_board.hex
```

Если `*.hex` один, прошивка стартует сразу.

### 2. Drag-and-drop

Можно перетащить `*.hex` на `flash.cmd`. В этом случае скрипт использует переданный файл как цель прошивки.

### 3. Командная строка

Поддерживаются как позиционный аргумент, так и именованные параметры.

Примеры:

```powershell
.\flash.cmd .\mcu_lts_board.hex
.\flash.cmd -HexFile .\mcu_lts_board.hex
.\flash.cmd -HexFile .\mcu_lts_board.hex -Lang ru
.\flash.cmd -HexFile .\mcu_lts_board.hex -Engine OPENOCD
.\flash.cmd -HexFile .\mcu_lts_board.hex -Engine CUBEPROGRAMMER -Probe JLINK
.\flash.cmd -HexFile .\mcu_lts_board.hex -Engine JLINK -Device STM32G431CB
.\flash.cmd -HexFile .\mcu_lts_board.hex -Target target/stm32g4x.cfg
.\flash.cmd -HexFile .\mcu_lts_board.hex -Serial 066AFF535548877187165246
.\flash.cmd -HexFile .\mcu_lts_board.hex -Sha256 84A7B05EB12A9986D903F3FCF5281385062A99089ACE0C947614C9ACF02F887C
.\flash.cmd -HexFile .\mcu_lts_board.hex -DryRun
.\flash.cmd -HexFile .\mcu_lts_board.hex -Silent
```

## Параметры

| Параметр | Назначение |
|---|---|
| `-HexFile <path>` | Явно задаёт путь к `*.hex` |
| `-Lang <ru\|en>` | Принудительно выбирает язык интерфейса и отчёта |
| `-Engine <OPENOCD\|CUBEPROGRAMMER\|JLINK\|path>` | Выбирает движок прошивки |
| `-Target <target/...cfg>` | Явно задаёт target-конфиг OpenOCD |
| `-Device <name>` | Явно задаёт имя устройства для SEGGER J-Link Commander, например `STM32G431CB` |
| `-Probe <STLINK\|JLINK>` | Выбирает тип отладчика для `STM32CubeProgrammer` |
| `-Serial <id>` | Явно выбирает конкретный ST-Link или J-Link по его serial |
| `-Sha256 <hash>` | Явно задаёт ожидаемый SHA-256 для `*.hex` |
| `-Silent` | Уменьшает количество вывода в консоль |
| `-DryRun` | Проверяет сценарий без реальной прошивки |

## Как выбирается движок

Скрипт поддерживает три движка:
- `STM32CubeProgrammer`;
- `OpenOCD`;
- `SEGGER J-Link Commander`.

Логика выбора:
- если движок задан явно параметром `-Engine`, используется он;
- если ранее был сохранён выбор в `.flash_engine`, он будет использован;
- если запуск идёт по прямому сценарию без лишних вопросов, скрипт предпочитает `STM32CubeProgrammer`, если он найден;
- иначе предлагается выбор из доступных вариантов.

## Как выбирается программатор

Если к ПК подключён один ST-Link или один J-Link, serial указывать не обязательно: движки обычно выбирают единственный отладчик своего типа самостоятельно.

Если подключено несколько ST-Link:
- можно сразу указать нужный параметром `-Serial`;
- если параметр не передан, скрипт покажет меню выбора;
- рядом с serial по возможности показывается распознанный тип МК;
- выбранный serial сохраняется в `.stlink_serial` для следующего запуска.

Этот же выбранный программатор затем используется и для `OpenOCD`, и для `STM32CubeProgrammer`.

Для J-Link доступны два сценария:
- `STM32CubeProgrammer` с параметром `-Probe JLINK`;
- прямой `SEGGER J-Link Commander` с параметром `-Engine JLINK`.

Примеры:

```powershell
.\flash.cmd -HexFile .\mcu_lts_board.hex -Engine CUBEPROGRAMMER -Probe JLINK
.\flash.cmd -HexFile .\mcu_lts_board.hex -Engine JLINK -Device STM32G431CB
```

Если serial J-Link указан явно, он используется для выбора конкретного отладчика. Если serial не указан, движок выбирает единственный подключённый J-Link самостоятельно. После успешного прямого запуска `-Engine JLINK` скрипт может извлечь `S/N` из лога и сохранить его в `.jlink_serial`.

Для прямого `SEGGER J-Link Commander` имя устройства обязательно. Его можно указать через `-Device`, например:

```powershell
.\flash.cmd -HexFile .\mcu_lts_board.hex -Engine JLINK -Device STM32G431CB
```

После первого запуска это имя сохраняется в `.jlink_device`.

Особенность `STM32CubeProgrammer + JLINK`: запись и верификация выполняются через `port=JLINK`, но аппаратный сброс через `-rst` для этого режима не используется, потому что на практике CubeProgrammer может успешно прошить и проверить файл, а затем вернуть ошибку только на этапе reset. Если нужен сброс и запуск после прошивки через J-Link, используйте прямой движок `-Engine JLINK`.

## Как выбирается target для OpenOCD

Если используется OpenOCD, скрипт пытается определить `target/*.cfg` последовательно:

1. из параметра `-Target`;
2. из сохранённого `.openocd_target`;
3. по данным `st-info`, если утилита доступна и удалось распознать подключённый МК;
4. по данным `*.ioc`, если такой файл найден рядом;
5. по имени `*.hex`;
6. вручную через ввод пользователя.

Если указанный или сохранённый `target/*.cfg` не существует внутри `OpenOCD scripts`, скрипт не использует его молча, а сообщает о проблеме.

### Как используется `st-info`

Для OpenOCD скрипт старается определить семейство STM32 по подключённому устройству через `st-info --probe`.

Сначала он ищет `st-info`:
- в `PATH`;
- в стандартных путях установки;
- в локальной `.tools\stlink`;
- при необходимости скачивает полный набор `stlink` tools из GitHub Releases.

Если `chipid` успешно найден, скрипт сопоставляет его с подходящим `target/*.cfg` для OpenOCD и пишет диагностическое сообщение в консоль.

## Проверка целостности `hex`

Перед запуском прошивки скрипт может проверить SHA-256 выбранного `*.hex`.

Поддерживаются два способа:
- через параметр `-Sha256`;
- через соседний файл контрольной суммы:
  - `firmware.hex.sha256`
  - `firmware.sha256`

Скрипт понимает как чистый hash, так и строку в стиле release-артефактов:

```text
84A7B05EB12A9986D903F3FCF5281385062A99089ACE0C947614C9ACF02F887C *mcu_lts_board.hex
```

Если контрольная сумма найдена и совпадает:
- в консоли показывается подтверждение SHA-256;
- прошивка продолжается как обычно.

Если контрольная сумма найдена, но не совпадает:
- прошивка не запускается;
- сценарий завершается с ошибкой;
- в `report.html` сохраняются ожидаемый и вычисленный SHA-256.

## Отчёт и лог

После каждого запуска формируются:
- `flash_log.txt`;
- `report.html`.

Дополнительно скрипт сохраняет историю сессий в `.history\`:
- `report_<timestamp>.html`;
- `flash_<timestamp>.log`;
- `session_<timestamp>.json`;
- `index.html` со списком последних сессий.

HTML-отчёт содержит:
- результат прошивки;
- состояние этапов;
- результат проверки SHA-256, если она выполнялась;
- сведения о хосте;
- сведения о пользователе и машине;
- сведения о программаторе / отладчике;
- сведения о микроконтроллере;
- лог утилиты;
- локальное время и UTC-время формирования отчёта.

Сведения из логов `STM32CubeProgrammer`, `OpenOCD` и `SEGGER J-Link Commander` извлекаются через отдельные наборы паттернов для каждого движка.

Поведение по умолчанию:
- при успехе отчёт только сохраняется;
- при ошибке отчёт сохраняется и открывается автоматически.

### История прошивок

Страница `.history\index.html` показывает последние сессии и содержит:
- локальное время запуска;
- результат;
- имя прошивки;
- использованный движок;
- длительность;
- ссылки на отчёт и лог конкретной сессии.

Основные файлы:
- `flash_log.txt` и `report.html` по-прежнему отражают только последний запуск;
- `.history\` хранит накопленную историю предыдущих сессий.

## Локализация

Поддерживаются два языка:
- русский;
- английский.

По умолчанию язык выбирается по системной локали. При необходимости можно явно указать язык параметром:

```powershell
.\flash.cmd -HexFile .\mcu_lts_board.hex -Lang en
```

## Dry Run

Режим `-DryRun` полезен для проверки сценария без записи во Flash. Он позволяет:
- проверить выбор файла;
- проверить выбор движка;
- проверить выбор конкретного ST-Link или J-Link;
- проверить контрольную сумму SHA-256;
- проверить определение target;
- получить лог и HTML-отчёт без реальной прошивки платы.

## Ограничения

- скрипт рассчитан на Windows;
- основной сценарий - прошивка STM32 через ST-Link или J-Link;
- логика отчёта ориентирована на `STM32CubeProgrammer`, `OpenOCD` и `SEGGER J-Link Commander`;
- `report.html` и `flash_log.txt` всегда отражают только последний запуск.

## Рекомендуемый сценарий для пользователя

Если нужен самый простой способ работы:

1. положить `flash.cmd` рядом с единственным `*.hex`;
2. подключить ST-Link или J-Link;
3. запустить `flash.cmd`;
4. при необходимости открыть `report.html` вручную.
