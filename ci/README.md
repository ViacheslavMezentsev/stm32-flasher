# Проверки CI

**Русский** | [English](README.en.md)

## GitHub

[CI](../.github/workflows/ci.yml) запускается на push любой ветки/тега,
pull request и вручную. Два независимых задания на `windows-latest`:

- Validate (5 минут): обязательные файлы, синтаксис PowerShell, формат версии,
  категории CHANGELOG и структура/трассировка ТЗ (`--strict`, Python 3.12).
- Regression (15 минут на оболочку): все `tests/Test-*.ps1` в Windows PowerShell
  5.1 и PowerShell 7. Матрица не отменяет вторую оболочку при отказе первой.

Логи каждого набора, время, код возврата и `results.json` загружаются даже при
ошибке; артефакты `test-logs-powershell` / `test-logs-pwsh` хранятся 14 дней.
Новый штатный `Test-*.ps1` включается автоматически; `tests/manual` не запускается.
Тесты используют заглушки, не требуют оборудования и не подтверждают работу на MCU.
Регрессии проверяют CMD-запуск, движки, RU/EN, конфигурацию, безопасность и упаковку.

## Локально

Нужны Windows, обе оболочки и Python 3.12 в PATH. Из корня клона:

```powershell
./ci/Invoke-Local.ps1
./ci/Invoke-Local.ps1 -Stage Validate
./ci/Invoke-Local.ps1 -Stage Regression -PowerShellExe pwsh
```

Первый вызов выполняет статические проверки и обе оболочки последовательно.
Это полный локальный прогон; один `pwsh` не заменяет матрицу PS5.1/7.
Можно задать `-PythonExe` и `-PowerShellExe` полными путями.
Не найденная оболочка или Python означает ошибку, а не пропуск проверки.
Ненулевой результат набора не скрывается, остальные наборы продолжают выполняться.
Статическая ошибка останавливает полный прогон до регрессий.

Логи по умолчанию: `tests/.tmp-ci-logs/1-powershell` и `2-pwsh`, Git их игнорирует.
`-LogDirectory` меняет корень логов. Сохраняйте нужные результаты до следующего
запуска: имена файлов повторно используются. Для отдельного теста:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/Test-Localization.ps1
pwsh -NoProfile -File tests/Test-Localization.ps1
```

`tests/Invoke-Tests.ps1` остаётся совместимой точкой запуска одной оболочки.
GitHub использует те же скрипты из `ci`, но запускает оболочки в отдельных jobs.
Полный прогон занимает несколько минут; по длительности одного набора нельзя
судить о зависании. Живой вывод и логи показывают текущий этап.

## Выпуск и аппаратура

[Release](../.github/workflows/release.yml) работает отдельно после ручной публикации
релиза владельцем: проверяет тег/версию и прикладывает ZIP и SHA-256. Описание
готовится в `docs/releases`. Workflow не заменяет проверку успешного CI коммита.
CMD находятся в корне ZIP, оба README поставляются вместе; `ci` не входит в ZIP.

После push владелец проверяет CI именно текущего коммита, затем выполняет `git land`.
Аппаратная приёмка отдельно: [правила и покрытие](../docs/testing.md).
